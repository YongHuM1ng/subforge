# 内部机制

## 翻译流程

```text
读取 SRT
  ↓
全文主题、风格、术语和 ASR 纠错分析（默认全文）
  ↓
分批翻译（每批附带前后文、与本批相关的纠错项）
  ↓
分批润色（使用目标语言前后文）
  ↓
校验 JSON 结果（ID、数量、非空）
  ↓
按目标语言自动折行
  ↓
保持编号和时间轴，输出 SRT
```

翻译和润色批次可以并发，但润色会在全部翻译完成后开始，以便使用相邻批次的目标语言译文作为参考。

## 上下文机制

`context = 3` 时，每批额外获得前后各 3 条字幕：

- 翻译阶段：原文前文 + 当前批次 + 原文后文
- 润色阶段：目标语言前文 + 当前批次 + 目标语言后文

提示词会明确告诉模型「本批是第 X/Y 批」，并说明前后文只用于理解语境，不要重复翻译或把后文内容提前写进本批。

## 提示词结构

提示词在 `src/srt_translator/prompts.py`，批次请求由 `pipeline.py` 组装：

```text
system   角色 + 输出格式（分析员 / 译者 / 校对编辑，三个阶段各一份）
user     [prompts] additional
         ## 任务 / 来源 / 翻译策略 / 长度与排版 / 纠错与术语（润色为「润色原则」）/ 输出
         <项目参考> 主题、风格、术语表          ← 以上整次运行不变，各批前缀完全一致
         <批次> <纠错参考> <前文> <后文> [<原文>] <输入>   ← 批次数据，<输入> 永远在最后
```

- 每条规则在一次请求里只出现一次；分析阶段不带翻译策略，润色阶段只带通用来源说明。
- 翻译取向只由「翻译策略」（`translation_fidelity`）决定；system 不写"忠实优先"之类的取向，避免和 `creative` 冲突。
- `<输入>` 每条带 `dur`（显示秒数），配合 `PROFILES` 里的阅读速度控制译文长度。
- 目标语言不是中文时，输出一节会要求不要混入中文用词或标点，并给出一句目标语言示例。
- 纠错项 `confidence`：high 直接采用，medium 结合上下文，low 只作参考。
- 分析结果不是合法 JSON（多见于长视频输出被截断）时会重试；纠错条数有上限（约字幕数的 1/4，20–150 条）。
- JSON 字段名和枚举值（`high/medium/low`、`asr/ocr/…`）保持英文，其余提示一律中文。

## 全文分析

全局分析默认使用**完整字幕**（不再截断到前 5 万字符），这样长视频后半段也能获得术语和纠错参考。

- 输入超过约 20 万字符时会在终端提示可能超出模型上下文。
- 如果接口限制严格，可以关闭 `global_analysis`。
- 分析结果不做缓存；需要复用时用 `--no-polish` / `--save-analysis` 写出 `.analysis.json`。

## 纠错项按批过滤

分析阶段产出的 `corrections` 只在本批（含前后文）范围内注入翻译/润色请求，避免长视频每个请求都重复携带全部纠错项。
提示词要求 `id` 只写一个编号；模型仍写成 `139-140`、`3、5` 时会展开，跨批的纠错项进入涉及的每个批次；无法解析的 id 视为全局纠错，每批都带。

## 无缓存

- 翻译不再写批次缓存；ASR 也不再保留跨运行的分片 JSON 或音频。
- 分析、翻译、润色都只在本进程内完成；中途失败后重跑会重新请求对应阶段。
- 翻译成功、只想重新润色时，用 `--no-polish` 写出 `<译文名>.analysis.json`，
  再用 `--translated <译文>.srt` 跳过分析和翻译。这个流程不依赖缓存。
- `workflow.py` 在翻译/润色失败后重跑时，仍会优先复用已有
  `<base>.asr[.lang].srt`，跳过 ASR。这是产物复用，不是临时缓存；
  要强制重新识别用 `--redo-asr`。
- `--keep-audio` 可以保留本次 ASR 的临时音频用于排查；默认结束后删除。

> 规划中的项目文件见 [项目文件设计稿](project-file.md)（尚未实现）。

## 内容审查与模型回退

- 审查/拒答的识别：HTTP 200 空 `choices`、`finish_reason=content_filter`、
  `message.refusal`，或 HTTP 400/403 的响应体命中审查关键词。
- 主模型最多请求 3 次（首次 + 2 次重试）。仍被拒时，如果配置了回退模型，
  当前批次和同阶段后续批次改用回退模型；回退模型也最多请求 3 次。
- 回退按阶段独立：分析回退不影响翻译/润色的主模型，翻译回退也不影响润色。
- 回退状态只在本次进程内有效；重新运行会重新从主模型开始。
- 并发批次中已经发出的请求不会被打断；回退只影响之后新发起的批次。
- 分析请求会打印 `[模型]`；翻译/润色批次的表格标题和 `--quiet` 进度行会带当前模型。
  回退时额外打印 `[回退]` 提示。

配置见 `config.toml` 的 `[models] fallback_enabled`、`fallback` 和
`analysis_fallback` / `translation_fallback` / `polish_fallback`。

## 自动折行

译文默认按目标语言折行，宽度按显示列计算（全角字符 2 列）：

| 语言 | 每条行数 | 每行 |
|---|---|---|
| 简体中文 | 最多 2 行 | 16 个汉字（32 列） |
| 日语 | 最多 2 行 | 20 个全角字符（40 列） |
| 英语 | 最多 2 行 | 42 个字符 |
| 韩语 | 最多 2 行 | 20 个全角字符 |

新增语种只需要在 `src/srt_translator/languages.py` 的 `PROFILES` 里加一条（排版、阅读速度、示例句），提示词和自动折行会同时生效。
目标语言名称到代码的映射在 `track.py` 的 `TARGET_CODES`；常见写法已覆盖，少见写法需要在那里补一条。

## 连接与并发

- `LLMClient` 复用同一个 `aiohttp.ClientSession` 和连接池，不会每个请求重新握手。
- 并发由 `asyncio.Semaphore` 控制（`--workers`）。
- HTTP 429/5xx 会按指数退避重试，优先遵守 `Retry-After`；服务端要求等待超过 120 秒时最多等 120 秒，避免 CLI 长时间挂起。
- 接口不支持当前 `structured_output` 时不会自动降级，而是报错并提示手动改成 `json_object` 或 `none`，避免静默改变请求。
  只有报错内容明确提到 `response_format` / `json_schema` 等字段才这样提示；`invalid model` 之类的普通 400 原样报出。
- ASR 同理：接口不接受 `timestamp_granularities` / `verbose_json` 时报错并提示改 `[asr] timestamps`。
  唯一保留的自动行为是：请求被接受、但响应里没有时间戳时，改用定长短切片重新识别（请求参数不变）。
- 任一 ASR 分片或翻译批次最终失败时，立即取消其余排队中的请求，不再为注定作废的结果付费。
- HTTP 200 但 `choices` 为空、`finish_reason=content_filter` 等按内容审查处理：
  主模型重试 2 次后按配置回退（见「内容审查与模型回退」）。
- 多个视频可以用 `--jobs N` 同时处理；总并发约为 `jobs × workers`。
- 分析/翻译/润色可以分别指定模型，未配置时统一使用 `[api] model`。

## 敏感和艺术内容

字幕可能来自影视、直播、游戏、ASMR、成人向作品、课程或其他创作内容。翻译和润色要求：

- 保留原文含义、语气、风格和表达强度
- 保留粗俗、冒犯性表达
- 保留 NSFW、色情和暴力内容
- 不审查、不弱化、不净化、不替换、不省略

ASR 纠错和语言润色只用于提高识别准确性与目标语言自然度，不用于改变创作内容本身。
